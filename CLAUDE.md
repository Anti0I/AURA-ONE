# AURA ONE

A product page for hardware that does not exist, built as a portfolio piece
about scroll-driven canvas rendering, procedural asset generation and
memory discipline.

**The founding constraint: every asset is generated from code.** No stock
photography, no purchased 3D model, no HDRI, no texture files, no audio files,
no paid API keys — for the author or for anyone opening the page. If a change
would introduce a binary asset that cannot be regenerated by
`npm run assets:all`, that is a design decision worth stopping to discuss, not a
detail.

Long-form reasoning lives at `src/app/engineering/page.tsx`, rendered for
visitors at `/engineering`. `README.md` is the contributor-facing version. This
file is the working knowledge that is expensive to re-derive.

## Commands

```bash
npm run dev              # Next 16 dev server, Turbopack
npm run verify           # typecheck + lint + 26 unit tests — run before every commit
npm run build            # production build
npm run audit:budget     # asset + JS budget gate; needs a build first
npm run test:e2e         # 36 Playwright tests, desktop + mobile projects
npm run test:a11y        # 12 axe / keyboard / reduced-motion tests
npm run assets:all       # regenerate every asset from primitives (~90 s)
node scripts/shoot.mjs   # screenshot the stage at five scroll positions
```

`npm run test:e2e` and `test:a11y` reuse a running dev server when there is one
and otherwise build and start their own. Both need `public/seq/` to exist; it is
committed, so a fresh clone works without a render.

## Hard rules

These are the ones that cause silent breakage rather than an error.

1. **Nothing that changes per frame goes through React state.** Per-frame values
   are written straight to `style` on refs, or to the mutable `telemetry` object
   in `src/store/transient.ts`. A full scrub of the stage causes zero
   re-renders; keep it that way. Zustand is for discrete state only — the
   material, the audio toggle, the story phase (which changes three times in
   total).

2. **There is exactly one animation loop**, `src/lib/scroll/rafBus.ts`. Never
   call `requestAnimationFrame` directly. Subscribers run in ascending priority:
   `INPUT` (0) may read layout, `RENDER` (100) may only write, `MEASURE` (200)
   observes the finished frame. Reading layout after a write in the same frame
   forces a synchronous reflow.

3. **`ImageBitmap` must be `close()`d.** Its memory lives outside the JS heap and
   GC will not reclaim it. `BitmapLRU` owns this; the unit tests assert on
   `close()` calls rather than on cache size, because skipping the call still
   *works* — it just leaks until the tab dies.

4. **Frames decode to the size they will be drawn**, not the size they were
   encoded. A bitmap costs the same whether or not the detail is visible.

5. **The shell renders neutral grey.** Every finish is a canvas composite at
   draw time. Baking a colour into the render means re-rendering 120 frames per
   variant.

6. **New below-the-fold sections are code-split.** Client wrapper +
   `next/dynamic({ ssr: false })` + `LazySection`, following
   `src/components/xray/XraySectionLazy.tsx`. Pass `LazySection` the section's
   `id` so the anchor exists before the section mounts.

7. **Numbers appear in one place.** The spec table and the encoder-written
   manifest are what the page and the engineering notes read. Nothing on this
   site may quote a frame count, a file size or a figure the build disagrees
   with — a spec sheet contradicting the paragraph beside it is the worst
   failure this project can have.

## Traps

Each of these cost real time. They are all still live.

**`tailwind-merge` and the custom type scale.** It assumes any unrecognised
`text-*` class is a colour, so `text-display text-ink` reads as a conflict and
the font size is silently dropped — a headline at 16px with no error anywhere.
`cn()` in `src/lib/utils.ts` registers the scale. Any new `@theme` key sharing a
prefix with a built-in group needs the same treatment.

**`globalCompositeOperation: "color"` cannot darken.** It takes hue and
saturation from the source and *luminosity from the backdrop*. Filling a bright
chrome render with near-black gives bright chrome and an invisible hue shift.
Lightness comes from `Material.exposure`, authored from the OKLab lightness of
the tint. See `src/lib/canvas/tint.ts`.

**A frame count is not a memory budget.** The same 24 frames are 39 MB decoded
at 640² and 199 MB at 1440². `BitmapLRU` takes both a count and a byte ceiling.

**Boot progress must be measured, not counted.** A resize bumps the decoder's
generation and the worker discards everything in flight, so counting replies
leaves the counter permanently short and the preloader never releases the page.
It only reproduces where layout settles late — every mobile test failed, desktop
never did. There is also a hard 12 s timeout, because an overlay that blocks
scrolling must always let go.

**Fixed `waitForTimeout` in canvas tests is a flake generator.** Sleeps tuned on
an idle machine fail under a parallel run. Poll for the actual state: `scrubTo`
in `tests/e2e/stage.spec.ts` waits for the frame to *change and then settle*
(waiting only for stability exits immediately, because right after a scroll the
canvas still holds the previous frame and is briefly perfectly stable).

**Satori needs explicit `display: flex`** on any element with more than one
child, and JSX makes `{X}.` two children. `src/app/opengraph-image.tsx` uses
template literals to keep text nodes single.

**ESLint blocks `setState` inside effects.** For platform capabilities that never
change, use `useClientValue` (`src/lib/useClientValue.ts`), which wraps
`useSyncExternalStore`. Never write a ref during render either — construct
lazily inside a callback instead.

**A `listbox` may contain only `option` and `group`.** The obvious
`ul > li > button role="option"` nests three invalid ARIA relationships. The
palette is the combobox pattern: the input keeps focus,
`aria-activedescendant` points at the active option.

**`playwright.config.ts` needs `testMatch`.** `testDir: "tests"` otherwise picks
up `tests/unit` and fails on the first vitest import.

scene and re-run the pipeline; do not hand-edit them.

## How the pieces work

**Stage.** Hero and scrollytelling share one canvas, so there is no seam to
cross-fade between "product at rest" and "product rotating". The pinned section
is `position: sticky` — there is no GSAP and no ScrollTrigger — and progress is
one `getBoundingClientRect` per frame during the INPUT phase. Camera framing is
a per-tier table of hero and story poses: desktop moves the product sideways to
make room for copy beside it, mobile moves it up because there is no beside.

**Frame decoding.** `fetch` + `createImageBitmap` both run in a worker; the main
thread never decodes. Two-tier queue with four concurrent requests so the frame
on screen jumps ahead of its own prefetches. A resize bumps a generation counter
and the worker drops stale work.

**Format split.** WebP for the sequence, AVIF for the two X-Ray stills. AVIF is
~18% smaller per frame but decodes ~3× slower with alpha, and a fast scrub
decodes several frames per animation frame. Bytes are one-time; decode is
per-scrub.

**Mobile variant** takes every second frame at 720px — 60 frames, 1.50 MB. Same
frames-per-scrolled-pixel density, half the decode work on the weakest hardware.

**Scanner.** Two renders from an identical camera, stacked, with a circular
window into the lower one. The lens is a fixed-size element that is
*translated*, and the copy of the artwork inside it is translated by exactly the
opposite amount. Animating `mask-image` or `clip-path` position recomputes the
mask on the compositor's critical path every frame.

**Audio** is entirely synthesised, ambient bed included. One `AudioContext`,
created on the first gesture. A hover tick can be pitched per element, which a
sample cannot do without shipping one per variant.

## Asset pipeline

```bash
npm run assets:all   # noise → prerender (~66 s) → encode (~20 s)
```

The encoded output is committed; the ~100 MB of master PNGs is not.

**Swapping in a Blender render.** The seam is the output contract, not the
scene. Drop into `assets-src/out/` and run `npm run assets:encode`:

- `aura_0001.png` … `aura_0120.png` — exactly 120, square, PNG RGBA with a
  transparent background (`Film → Transparent`)
- `xray-outer.png`, `xray-inner.png` — 16:9, from an **identical camera**

Two constraints carry over: render the shell neutral grey, and keep the phase
boundaries (1–36 rotate, 37–84 explode, 85–108 push into the core, 109–120
reassemble). `src/data/story.ts` caption windows are asserted against them by a
unit test. If the X-Ray camera moves, regenerate `hotspots.json` with
`npm run assets:prerender` rather than editing it.

## Testing

The scrollytelling cannot be checked by asserting on the DOM — everything that
matters happens inside a canvas React never re-renders — so those tests read
pixels: coverage, frame fingerprints, mean luminance for the finish tests.

- `tests/unit/` — vitest. LRU eviction and `close()`, caption timing, the power
  model against the copy, frame-rate-independent damping.
- `tests/e2e/` — Playwright, `desktop` and `mobile` projects.
- `tests/a11y/` — axe on the chrome, on every lazy section once mounted, on the
  palette while open, on `/engineering`; plus the skip link, keyboard
  reachability and the reduced-motion path.

CI (`.github/workflows/ci.yml`) builds once and reuses it for both Playwright
suites. There is no Lighthouse job: its stable categories are already covered by
axe and the budget gate, and a performance score from a shared runner flaps
enough that people learn to ignore it.

## Conventions

- TypeScript strict, plus `noUncheckedIndexedAccess` and `verbatimModuleSyntax`
  (use `import type`).
- Comments explain *why*, especially where the obvious implementation is wrong.
  Several of the traps above are documented at their call site; keep that.
- Design tokens live only in `src/app/globals.css`. No raw hex outside it,
  except where satori cannot read CSS (`opengraph-image.tsx`, commented).
- All numbers rendered to the user carry `data-numeric` for tabular figures.
- Conventional Commits, and commit messages state what was found and fixed, not
  just what changed.
